# 波形降采样保真与数字跳变计数

## 实现边界

- 数字边沿使用状态变化样本的显示时间，支持脚本时间、样本序号、采样频率三种时间轴。
- `WaveQueryView::digitalSegments` 先通过多级摘要跳过恒定区间，只枚举预算内的真实边沿。同像素多次翻转或图元预算不足的区间使用低透明度活动带；放大后重新查询原始数据。
- `compressed_steps` 与 `activity_band` 配置继续兼容，两者都不再把桶内变化搬到桶末时间。
- `WaveSummaryIndex` 仅对开启 `bit_display` 的通道分配翻转计数块。子块合并补计交界变化，追加、裁剪、导入、重置及开关数字显示同步维护。
- 总数按新状态样本时间落入闭区间 `[minTime, maxTime]` 统计，上升和下降各计一次。左邻样本只提供前态，首个留存样本不凭空计数。
- 每条轨道显示通道编号、bit 与总次数；没有有效历史结果时拖动期间显示 `--`，有效的零次数显示 `0 次`。同 bit 不同通道分别统计。
- 数字几何、总数与概览分别缓存。按下鼠标、概览拖动、视窗动画期间不执行总数查询，松手并结束动画后对最终范围刷新，同键复用。
- 概览直接查询原始数据的时间桶极值，低密度绘制真实折线，高密度绘制各桶时间范围内的最小值至最大值覆盖区域。空桶不补零，常量保持可见，归一化只改绘制副本。
- 概览缓存键包含数据版本、历史代次、通道、时间轴、历史范围、实际宽度、预算及显示变换，不包含主图视窗。
- 原始样本、协议和保留策略未修改。顶点上限未增加：主图与概览共享预算，预留一成给坐标轴和覆盖物；数字通道先预留标签字形成本，再分配几何。

预算收紧会相应缩短选择“按绘制点数决定默认时宽”时的初始窗口。
例如单通道 Glow、60000 顶点上限、800 像素宽、1000 Hz 时，
预算由 800 点变为 794 点，初始时宽为 0.794 秒。

## 验证命令

2026-09-21，在当前机器独立配置 `build-wave-fidelity`：
Ninja、MinGW GCC 15.2、Release；复用已有 GLFW 源码缓存。
可执行文件输出到该构建目录的 `bin`，未覆盖其他构建目录的应用。

```powershell
cmake --build build-wave-fidelity --parallel 12
ctest --test-dir build-wave-fidelity --output-on-failure --timeout 60
.\build-wave-fidelity\bin\protoscope_wave_ui_benchmark.exe --gl
.\build-wave-fidelity\bin\protoscope_wave_ui_benchmark.exe --verify --gl --capture build-wave-fidelity/captures
git diff --check
```

完整 CTest：8/8 目标通过，14.43 秒。

新增查询回归覆盖百万样本稀疏翻转、密集区与窄脉冲、像素及图元预算变化、
三种时间轴、窗口端点、多 bit、块边界、追加、裁剪、重置、重复时间导入、
数字索引开关与释放。计数预期由独立逐样本扫描生成。
概览测试对长正弦、调幅波、正负尖峰、常量、非均匀采样与空桶逐桶核对原始极值，
并覆盖负缩放、原始折线和归一化不改源数据。

多帧测试覆盖冻结统计、动画结束刷新一次、同键不重查、不同通道分别计数、
分屏可见轨道、主题切换、480 像素窄窗口、概览缓存失效与主图平移复用。
原有游标、bit/模拟波形悬停及交互测试仍包含在完整测试集中。

## OpenGL 结果

四路模拟加一路展开 32 bit，10 万及 100 万可见样本，实际保留量另含
30000 点平移余量。预热后平移 300 帧，计入 OpenGL 提交、`glFinish` 与交换缓冲。
非 FFT 场景包含概览、轨道标签与冻结计数，松手帧另外统计。

| 模式 | 10 万点 P95 / ms | 100 万点 P95 / ms | 百万点峰值顶点 |
| --- | ---: | ---: | ---: |
| 普通 | 3.304 | 3.973 | 30948 |
| Glow | 3.348 | 4.207 | 27540 |
| 堆叠 | 3.056 | 4.186 | 27636 |
| 分屏 | 1.126 | 1.704 | 33480 |
| GPU 余辉交互轨迹 | 2.951 | 4.216 | 27568 |
| CPU 余辉交互轨迹 | 2.888 | 4.221 | 27568 |
| FFT | 1.125 | 1.235 | 7362 |
| 普通，30000 顶点上限 | 1.651 | 2.019 | 18508 |

所有上述交互场景 P95 小于 16.7 ms。60000 上限场景峰值为 33632，
30000 上限场景峰值为 18508；每帧及松手帧都断言真实 `TotalVtxCount` 不超上限。
分屏默认只显示前四行，第五行数字通道位于滚动区外，不以此模式的数据证明
32 bit 同时可见性能；数字分屏由独立双通道测试验证。FFT 模式没有数字计数或概览。

| 单独计时项目 | 10 万点 | 100 万点 |
| --- | ---: | ---: |
| 首次生成、追加全部五通道及索引 / ms | 9.548 | 79.016 |
| 已有数字通道启用计数索引 / ms | 2.140 | 17.305 |
| 再追加一个数字样本 / ms | 0.419 | 3.062 |
| 32 bit 松手计数 / ms | 0.019–0.024 | 0.017–0.023 |
| 五通道摘要存储估计 / bytes | 1184512 | 9286528 |

追加计时包含真实缓冲区操作及可能发生的 vector 扩容，不是只测索引命中。
内存为摘要和计数有效载荷及层容器估计，不包括原始样本、分配器、deque 管理、
字体或 GPU 资源，不等同于进程驻留内存。

普通模式松手整帧分别为 1.964 / 0.739 ms。
CPU Texture 余辉松手整帧分别为 36.727 / 38.391 ms，超过 16.7 ms；
该帧计数仅为 0.024 / 0.023 ms，其余耗时未进一步拆分，不能宣称松手整帧达标。
首次启用百万点数字索引的 17.305 ms 同样单列，不混入预热后的交互 P95。

修改前 `b4185b7` 的独立 Release 普通模式基线为 2.400 / 3.562 ms，
总顶点峰值 33112。旧基准未绘制概览和计数文字，不能将这组差值视为相同负载的性能回归比值。
