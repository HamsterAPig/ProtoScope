# 工业控件与持久化执行计划

## 自动推进约定

用户已明确要求持续、自动推进完整方案。

- 每个阶段实现、验证并按行为边界提交后，直接执行下一项。
- 阶段性提交、测试通过和进度汇报不是停止点，不等待用户重复要求“继续”。
- 仅在用户主动暂停、需要明确确认的高风险操作、无法自行解除的阻塞或执行环境中断时暂停。
- 暂停或上下文交接前记录实际阻塞、未完成项和下一条可执行操作；
  恢复后先读取本计划及 `industrial-storage-progress.md`，从未完成项继续。
- 不以缩减验收范围代替完成原方案，不声称未运行的长期测试通过。
- 此约定不代表对话结束后存在后台代理或自动唤醒能力。

## 验证与边界

- 各模块新增回归测试；普通新增 CTest 目标超时 60 秒。
- 每次提交前运行差异检查、构建和相关测试；共享接口变更运行全量 CTest。
- 已有 `build` 使用 MinGW Makefiles，不能直接改写成 Ninja。
- GUI 至少构建验证，并区分自动化结果与尚未进行的人工交互验收。
- 记录发布成功不代表已落盘；长期记录不能静默丢弃后仍显示正常。
- 历史数据不进入 ControlValue 或全量 UI 快照，KV 不参与记录清理。
- 用户既有变更和无关 `.agents/zdocs/inbox/reflections` 文件不纳入提交。

实际提交、验证输出及剩余边界统一记录在 `industrial-storage-progress.md`。
